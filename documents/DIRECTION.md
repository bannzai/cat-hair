# 方向性: Oh My Fur! (リポジトリ名は cat-hair)

## 仮説

Steam で 300〜900 円の短編インクリメンタルを買って数時間で遊び切る PC のプレイヤーは、同種の作品に「短すぎる・唐突に終わる」「終盤が待つだけになる」という不満を持っている。猫の毛を手で 1 本ずつ抜くみみっちさを写実寄りの一人称 3D で気持ちよく・アホらしく見せ、取りこぼし・猫がまた落とす毛・探し物を傷めない道具の持ち替えで自動化の後もやることを残せば、手で取る段階の手触りと、全自動にした時の「最高」の両方が遊ぶ理由になる。

## 判定基準

評価レポートの全文は作るかの判断の issue にある (評価時点のスナップショット。以後の更新は本文書だけに書く)。ウィッシュリスト数を castle の skill かコマンドで読む経路が無いため、その行の計測元はストアページを出す時に決め直す。

## 必要な機能

bannzai が作るかの判断の issue ( https://github.com/bannzai/cat-hair/issues/2 ) で決めた一覧 (2026-11-26)。遊びの中身の全文は [PROJECT.md](PROJECT.md)。最初の触れる版 (屋敷を、手で取る段階から自動化まで遊べる版) に入れるのは上から 8 つ。道具は、PROJECT.md「道具」の表の物を最初から全部作る (建物ごとの専用の道具は、建物 2〜4 の項目で作る)。

- [x] 毛の描画の試作: 1 部屋に毛を置き、本数ごとの描画の可否と描画時間を CI で測る (`make hairbench`)。レンダラを決め直して ADR に書く
- [ ] 屋敷と一人称の土台: 屋敷の 1 階 (数部屋)、一人称の移動と視点、床・家具・布の表面、表面ごとの毛の本数を 1 か所で持つ状態、残り本数の表示、セーブと読み込み。開発者が調整できる値 (毛の本数・埋める探し物の数・屋敷の広さ・物の数・部屋の数) と、それをゲームの中で変える開発者向けの画面を最初から持つ
- [ ] 手で抜く: 毛をつまんで引くと伸びてから抜ける、効果音とカウント、珍しい毛と図鑑、手の強化
- [ ] お金と手持ちの道具: 買取業者に毛を売る、住人の機嫌と掃除代、道具の購入とレベル (取りこぼしが減る)、取りこぼしの表示、表面ごとの得意・不得意、消耗品 (粘着ローラーの紙)。道具は 手・ピンセット・ガムテープ・ゴム手袋とスポンジ・粘着ローラー・掃除機・毛を光らせるライト・ブラシ
- [ ] 猫と掃除ロボット: 猫の通り道と昼寝の場所・また落とす毛、掃除ロボットの配置と巡回の順、何もしなくても数字が増える状態
- [ ] 大型の道具と加工: 業務用の吸引車・建物を覆う粘着シート・毛の加工機と色の仕分け・毛を運ぶダンプカー・アンドロイド
- [ ] 自動テストプレイ: bot が手で取る段階から自動化まで headless で進めて所要時間を集計する `make simulate` と、描画付きの録画 `make playtest`
- [ ] BGM と効果音 (CC0 の既製の素材。設定画面でオン・オフ)
- [ ] 見た目の試作: 参考の動画の方向で屋敷の 1 部屋と画面の表示を作り、撮った画面を bannzai に見てもらう
- [ ] 見た目の方向の反映 (見た目の試作を見てもらって決めた後)
- [ ] 探し物と依頼: 住人の依頼、探し物を傷めない道具の持ち替え、服の毛を取り切る依頼、逃げた猫を連れ戻す
- [ ] 次の建物へ進む: 住人全員がご機嫌で進める、成績、手の強化の持ち越し
- [ ] 建物 2〜4 (ホテル・猫島・街全体) と専用の道具、エンディングの 1 枚絵
- [ ] Steam の公開の経路: Steamworks 連携 (別 ADR)、ストアページ、題名『Oh My Fur!』の同名・商標の確認 (bannzai が公開に進むと指示した後)

## デザインの方向

既製の 3D モデルを入れて写実に寄せる (2026-11-27 に owner が見た目の試作 (`documents/design/look-prototype-2026-11-26/`) の 3 枚を見て選んだ。発言の原文は https://github.com/bannzai/cat-hair/issues/34#issuecomment-7209673362 )。家具・手・掃除ロボットを、ライセンスが CC0 の既製の 3D モデルに置き換え、床・壁・光は試作の物を使う (選んだ選択肢の中身。issue #34 の本文)。絵は写実寄りで真面目な見た目にし、やっていることのくだらなさとの落差で笑わせる (owner が選んだ案)。`~/.claude/documents/guides/visual-patterns-to-avoid.md` の項目を使わない。実在の掃除用品・家電のメーカーの名前と意匠は使わない。

参考にする動画 (owner の指定。2026-11-26。発言の原文は https://github.com/bannzai/cat-hair/issues/4#issuecomment-7183068745 )。2 本とも、干し草の山から針を探すゲームの実況。

- https://www.youtube.com/shorts/VWcBjQ2nwww (題「1300万本の草から1本の針を探すとんでもないゲーム」)
- https://www.youtube.com/watch?v=7zgcjF2Sxuw (題「1359万本の干草からたった1本の針を見つけ出す」)

agent が見たのは、動画のサムネイルと途中の 1 コマの静止画 4 枚だけで、動画の本編 (動き・演出・音) は見ていない (2026-11-26。開発マシンの負荷を避けて動画を取得しなかった)。静止画から読み取れたこと (幅 480〜1280 の画像からの読み取りで、画面の文字は一部しか読めていない):

- 一人称の 3D で、写実寄りの光と影。乾いた地面・木の壁・青空の下に、画面の半分を占める大きな干し草の山があり、1 本ずつの細かさが山の表面に見える
- 画面の表示は控えめ: 右上に所持金と残り本数の数字、下の中央に番号付きの道具の枠の並び、左上に今やることの短い案内、最下段にキーの案内
- 自動化が進んだ絵 (2 本目のサムネイル) では、山のまわりをロボットの腕・ベルトコンベア・機械が囲み、手で取っていた物を機械が運んでいる

参考にするのは方向 (写実寄りの一人称・量の多さが一目で分かる絵・控えめな画面の表示・自動化の機械が並ぶ絵) で、その作品の画面の並び・素材・意匠は写さない。

## agent に任せること

bannzai が判断しなかった事項。ここに無い問いも任せる側に落ち、agent は可逆な方を選んで「決めたこと」に記録する。

- 屋敷の毛の総本数、道具ごとの取れる本数の伸び方、各道具の値段、掃除代の額、住人がご機嫌になる線 (自動テストプレイの結果で決める)
- 屋敷の間取り、住人と猫の数・名前・見た目、買取業者の見た目
- 操作の割り当て (キー・マウス)、画面の並び
- レンダラ (毛の描画の試作の結果で決め、ADR に書く)
