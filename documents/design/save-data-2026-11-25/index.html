2026-11-25 に agent が書いた案。作るかの判断の issue で、必要な機能の一覧と一緒に見てもらうための資料。実装はまだ無い。

見てほしい点

  • 毛は 1 本ずつの位置を保存せず、面ごと・色ごとの本数だけを保存する。読み込むと、同じ本数の毛が面の上に並び直る (数百万本の位置を保存しないため)
  • お金・道具・掃除ロボットの巡回は、今いる建物の進行 (BuildingProgress) に置く。次の建物へ進むと、この進行を新しく作り直すので、お金と道具は置いていく形になる
  • 次の建物へ持ち越すのは、手の強化 (hand_upgrade_levels)・図鑑 (found_rare_hair_ids)・終えた建物の成績 (building_records) の 3 つ
  • 協力プレイを後で足す時も、お金と手の強化は参加者ごとには持たず、この 1 つの保存データに置く (起票元の issue の「お金は全員で 1 つ」「手の強化は全員で共有」に合わせた)
  • 道具ごとの違い (どの表面が得意か・レベルごとの取りこぼし・探し物を傷めるか・消耗品) は、道具の定義 (ToolDef) が道具 1 つずつに持つ。同じ系統の道具でも別の値にできる

保存する型 (GDScript。user:// に 1 ファイル)

## セーブデータ全体。建物をまたいで残る物と、今いる建物の進行を持つ
class_name SaveData
extends Resource

## 持ち越す手の強化。強化の種類 (指先の器用さ・一度につまめる本数等) ごとのレベル
@export var hand_upgrade_levels: Dictionary[StringName, int]
## 図鑑に載った珍しい毛の種類
@export var found_rare_hair_ids: Array[StringName]
## 終えた建物の成績 (終えた順)
@export var building_records: Array[BuildingRecord]
## 今いる建物の進行。次の建物へ進むと新しく作り直す
@export var building_progress: BuildingProgress


## 終えた建物 1 つの成績
class_name BuildingRecord
extends Resource

## どの建物か (屋敷・ホテル・猫島・街全体)
@export var building_id: StringName
## 住人全員がご機嫌になるまでにかかった時間 (秒)。表示するだけで報酬には効かない
@export var clear_seconds: float
## 住人に返した探し物の数。持ち越す手の強化の量に効く
@export var returned_found_item_count: int


## 今いる建物の進行。お金と道具は建物ごとに持つ
class_name BuildingProgress
extends Resource

## どの建物か
@export var building_id: StringName
## この建物で遊んだ時間 (秒)
@export var elapsed_seconds: float
## 所持金
@export var money: int
## 面ごとに残っている毛
@export var surface_hairs: Array[SurfaceHair]
## 取ってまだ売っていない毛と、加工した物
@export var hair_stocks: Array[HairStock]
## 買った道具
@export var owned_tools: Array[OwnedTool]
## 掃除ロボットごとの巡回の順
@export var robot_routes: Array[RobotRoute]
## 住人ごとの機嫌 (0.0 = 不機嫌 〜 1.0 = ご機嫌)
@export var resident_moods: Dictionary[StringName, float]
## 探し物ごとの状態
@export var found_items: Array[FoundItemProgress]


## 建物の中の 1 つの面 (居間の床・ソファ・住人のスーツ等) に残っている毛
class_name SurfaceHair
extends Resource

## 建物のどの面か
@export var surface_id: StringName
## 色 (白・黒・三毛) ごとの残り本数
@export var hair_counts: Dictionary[StringName, int]


## 取ってまだ売っていない毛、または加工した物の在庫 1 種類
class_name HairStock
extends Resource

## 毛の色 (白・黒・三毛・混ざった物)
@export var hair_color: StringName
## 形 (毛のまま・毛玉・フェルト・人形)
@export var form: StringName
## 数 (毛のままなら本数、加工した物なら個数)
@export var count: int


## 買った道具 1 つ
class_name OwnedTool
extends Resource

## どの道具か (ToolDef の id)
@export var tool_id: StringName
## 道具のレベル。上げると取りこぼしが減る
@export var level: int
## 消耗品の残り (粘着ローラーの紙の枚数等)。消耗品の無い道具は 0
@export var consumable_count: int


## 掃除ロボット 1 台の巡回
class_name RobotRoute
extends Resource

## どの掃除ロボットか (OwnedTool の tool_id)
@export var tool_id: StringName
## 回る部屋 (回る順)
@export var room_ids: Array[StringName]


## 探し物 1 つの状態
class_name FoundItemProgress
extends Resource

## 探し物の状態
enum Condition {
	## 毛の山の中にあり、まだ見つけていない
	HIDDEN,
	## 見つけたが、毛が付いたまま
	FOUND,
	## 合う道具で毛を取り切った
	CLEAN,
	## 合わない道具で取って傷めた
	DAMAGED,
}

## どの探し物か (FoundItemDef の id)
@export var found_item_id: StringName
## 今の状態
@export var condition: Condition
## 持ち主の住人に返したか
@export var is_returned: bool

保存しない定義 (ゲームに同梱する。道具 1 つずつに .tres を置く)

## 道具 1 つの定義
class_name ToolDef
extends Resource

## 道具の系統
enum Kind { PICK, FIND, CARRY, CAT, PROCESS }

## 道具の id
@export var id: StringName
## 系統 (取る・見つける・運ぶ・猫に使う・加工する)
@export var kind: Kind
## レベルごとの値段 (0 番目が買う値段、以降がレベルを上げる値段)
@export var prices: Array[int]
## レベルごとの取りこぼしの割合 (0.0〜1.0。レベルが上がるほど小さい)
@export var miss_rates: Array[float]
## 表面の種類ごとの得意さ (取りこぼしの割合に掛ける。1.0 より小さいほど得意)
@export var surface_miss_multipliers: Dictionary[StringName, float]
## 1 回かけた時に範囲に入る毛の本数の上限
@export var hairs_per_use: int
## 消耗品 1 つの値段 (消耗品の無い道具は 0)
@export var consumable_price: int
## 探し物をまとめて取ると傷めるか (掃除機・吸引車は true)
@export var damages_found_items: bool

class_name FoundItemDef
extends Resource

## 探し物の id
@export var id: StringName
## 持ち主の住人
@export var owner_resident_id: StringName

@export var safe_tool_ids: Array[StringName]

@export var clean_reward: int
## 傷めて返した時に上乗せされる額
@export var damaged_reward: int

当てた設計の問い

  • 利用者が頼んだ言葉に無い概念を足していないか: 起票元の issue に無い名詞は form (毛玉・フェルト・人形の形) だけで、これは issue の「毛の加工」の例から取った。レベル・消耗品・機嫌・成績は issue にある
  • 保存する値は必要な値そのものか: 本数・お金・レベルをそのまま保存し、段階やランクに置き換えていない
  • 個々の物ごとの違いを表せるか: 道具ごとの違いは ToolDef が道具 1 つずつに持つ。吸引車・ダンプカーのように動き方が違う道具の動きは、定義の値ではなく道具ごとのシーンとスクリプトで作る
